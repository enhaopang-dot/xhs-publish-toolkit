## ⚠️ 先说清楚风险

**这个仓库里最有价值的是 `PITFALLS.md`，不是脚本。**

自动化发布工具与平台用户协议存在冲突。已知事实：**2026-11-07，使用模拟键鼠发布被判为 AI 托管，账号被禁发 7 天。** 放慢动作只能降低「行为节奏」这一维的检测概率，账号画像、内容指纹、设备指纹不受影响。开源后大量用户跑同一套脚本，行为特征高度雷同，更容易被平台批量识别。

## 这是什么

两部分：

### 1. PITFALLS.md · 发布坑位清单

各平台发布链路的真实踩坑记录，313 行：

- 小红书：封闭影子根按钮、遮挡抽屉、超时假成功、输入事件失效、跳转验证
- 抖音：文件上传卡 0%、驱动级输入需求
- 视频号：cookie 生命周期、扫码登录态维护
- 公众号：草稿接口、封面设置

这部分比代码值钱。你要做发布自动化，先读这个再动手，能省几天试错。

### 2. 两个脚本

| 文件 | 作用 |
|---|---|
| `publish_xhs.py` | 小红书发布：Playwright 驱动浏览器，填写标题正文、上传图片、点发布 |
| `pull_xhs_data.py` | 拉取小红书笔记数据 |

## 用法

```bash
pip install playwright
playwright install
python publish_xhs.py --note <内容文件> --images <图目录>
```

首次运行需要在弹出的浏览器里手动登录一次，之后复用登录态。

## 核心设计

- **复用持久化浏览器配置**：不用每次扫码，登录一次由浏览器自己维护
- **动作放慢**：关键操作之间加随机延迟，模拟真人节奏
- **关键节点截图**：每一步留证据，失败时能定位到具体哪一步
- **发布前核对账号**：以页面昵称和 ID 为准，不看 cookie 是否有效

## 注意

- 仓库内**不含任何 cookie、账号凭证、登录态**
- 各平台的 DOM 会频繁改版，脚本很可能在某次更新后失效
- 平台规则随时变，本文档的结论带时间戳
